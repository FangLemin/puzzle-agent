## 当前架构

项目保持纯 Python 标准库服务端渲染，不引入 Java、Node、Vue、React 或前端构建工具。

核心模块：

- `puzzle_ops/server.py`：本地 HTTP action 路由。
- `puzzle_ops/renderer.py`：Python 服务端页面渲染。
- `puzzle_ops/agents.py`：核心业务 Agent、RAG、Harness、同步、Memory 编排。
- `puzzle_ops/rag.py`：文档加载、chunk、BM25/向量召回、rerank、Milvus/Qdrant adapter、检索评估。
- `puzzle_ops/harness.py`：Agent Harness 样本、case、run、失败复盘和指标聚合。
- `puzzle_ops/storage.py`：SQLite 主数据、四层 memory、RAG feedback、缓存。
- `puzzle_ops/vision_llm.py`：Qwen/OpenAI 视觉语言模型适配。
- `puzzle_ops/image_generation.py`：好图衍生生成 provider 抽象和 DashScope/Mock provider。
- `puzzle_ops/feishu.py`：真实飞书写入和 mock fallback。

## Memory 设计

当前 memory 拆为四层：

- 感知记忆：图片解析、VLM 观察、本地视觉特征。
- 短期记忆：当前任务链路状态，例如 generation trace、试新过程状态。
- 长期记忆：运营确认长期有效的价值观、规则、经验。
- 结构化事实：主体、国家、运营 tag、图片路径、价值观标签、风险标签等可评测字段。

治理能力：

- 支持 active / expired / promoted / retired 状态。
- 支持人工晋升为事实或长期记忆。
- 支持停用错误 memory。
- active 且 RAG ready 的 memory 会进入价值观与审核 RAG。
- 价值观人工修正会写入 working memory、facts memory 和 RAG eval feedback。

## RAG 设计

离线阶段：

- 文档来源：日本/法国价值观规则、审核规则、四层 memory、历史样本事实、真实 human_gold 样本。
- 文档加载：本地 `StaticDocumentLoaderAdapter`、`FileDocumentLoaderAdapter`、`RetrievalCaseLoaderAdapter`。
- 文档切割：按标题/语义段落优先，默认 `chunk_size_tokens=600`、`chunk_overlap_tokens=100`。
- 父子结构：保存 parent document 与 child chunk，页面展示 citation、parent、title、text。
- 入库：当前支持 SQLite 本地 chunk store、Qdrant adapter、Milvus adapter。
- Embedding：推荐 DashScope `text-embedding-v4`。
- Rerank：推荐 DashScope `qwen3-rerank`。

在线阶段：

- Query rewrite：将运营问题补充国家、主体、价值观、风险等业务上下文。
- 多路召回：BM25 词面召回 + embedding/vector store 召回。
- 候选合并：合并 BM25、向量和父子 chunk 候选。
- Rerank 精排：本地规则 fallback 或 Qwen rerank 远程精排。
- Prompt 拼接：问题 + 精排 chunk + citation ids + 限制说明。
- 生成：生成式 RAG 可调用 Qwen 文本模型；价值观大师会把 RAG citation 与 VLM 图片证据一起用于判断。
- 防幻觉：页面展示引用依据，prompt 要求基于资料回答；未配置远程 provider 时明确 fallback，不伪造远程调用。

检索评估：

- `hit@5`
- `mrr@5`
- `precision@5`
- `recall@5`
- `ndcg@5`
- 失败 case diagnosis，例如 BM25 缺召回、向量缺召回、rerank 排序失败。

## Harness 设计

Harness 覆盖任务：

- `trial_parse_eval`：试新图三段式解析是否符合标准。
- `value_match_eval`：价值观判断是否引用当前图像证据和 RAG 依据。
- `audit_eval`：审核风险是否召回。
- `grade_predict_eval`：S/A/B/C/D 预测是否接近真实等级。
- `derive_generation_eval`：好图衍生生成链路是否可追踪、可审核。
- `feishu_sync_eval`：飞书字段完整性与附件 ready 状态。

Harness 页面能力：

- 数据集概览，区分真实样本和合成 demo。
- 失败样本复盘。
- 人工修正入口。
- HITL 修正导出。
- Argilla / Label Studio 本地导出。
- RAG artifacts 和 citation trace。
- RAG 远程调用率、缓存命中率、降级率。

## 多模态与生成

图片理解：

- 默认视觉模型：`qwen3-vl-plus`。
- 支持 OpenAI fallback，但当前推荐 Qwen/DashScope。
- 未配置 key 时只做本地像素解析，不伪造主体识别。
- 试新解析标准输出为三段：主体内容、色彩氛围、构图环境。

好图衍生：

- 已有 `ImageGenerationProvider` 抽象。
- `mock` 只用于 UI/Harness 测试，不作为真实生产图。
- `dashscope` 可接通义万相生成参考图。
- 生成图必须经过二次 VLM 解析、审核规则复检、人工确认后才可同步飞书附件。

## 飞书同步

已完成：

- 真实飞书表格/多维表格写入。
- 未配置密钥时明确失败，不清空提需表。
- 图片附件同步链路要求真实 file token，不再伪造附件对象。
- 生成图和上传图同步前需要通过可同步资格判断。

注意：

- `.env` 被 `.gitignore` 忽略，不会提交密钥。
- 飞书字段必须与线上表字段一致，否则飞书会返回 FieldNameNotFound。
- 附件字段必须使用飞书 `file_token`。

## 真实运行需要的外部条件

视觉理解：

```env
VISION_LLM_PROVIDER=qwen
QWEN_API_KEY=...
QWEN_VISION_MODEL=qwen3-vl-plus
```

RAG 远程模型：

```env
RAG_ENABLE_REMOTE_CALLS=true
RAG_EMBEDDING_PROVIDER=dashscope
RAG_EMBEDDING_MODEL=text-embedding-v4
RAG_RERANK_PROVIDER=dashscope
RAG_RERANK_MODEL=qwen3-rerank
```

Milvus：

```env
RAG_VECTOR_STORE_PROVIDER=milvus
RAG_VECTOR_STORE_SEARCH_ENABLED=true
MILVUS_URI=http://127.0.0.1:19530
MILVUS_COLLECTION=puzzle_ops_rag
MILVUS_TOKEN=
```

飞书：

```env
FEISHU_APP_ID=...
FEISHU_APP_SECRET=...
FEISHU_SPREADSHEET_TOKEN=...
FEISHU_SHEET_RANGE=...
```

真实评测集：

```env
PUZZLEOPS_HARNESS_DATASET=/absolute/path/to/gold_samples.csv
```
