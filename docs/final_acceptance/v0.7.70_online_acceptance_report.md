# PuzzleOps v0.7.70 Online Acceptance Report

日期：2026-08-13

本报告用于把 v0.7.64-v0.7.70 的正式上线架构补齐工作收口成一份可交付材料。它面向两类读者：

- 运营团队负责人：确认 6 人团队上线前需要配置什么、验收什么、哪些风险仍需人工管控。
- 面试官/GitHub 读者：理解这个项目不是单机 demo，而是围绕 Agent Harness、RAG、Memory、HITL、评测、飞书落地和上线工程化做了闭环。

## 1. 当前版本结论

当前版本：v0.7.70。

上线形态：

- 单人 demo：Python 标准库本地页面，`http://127.0.0.1:5199`。
- 6 人团队服务化入口：FastAPI，`http://<服务器IP>:8000/docs`。
- 事务主库：PostgreSQL，SQLite 保留为本地 fallback。
- 图片对象：阿里云 OSS，数据库只存 `object_key/public_url/hash/file_token`。
- 向量检索：Milvus/Zilliz，继续只负责 RAG/图像 embedding 检索。
- 异步任务：Redis/RQ，可选启用；未配置时保留本地数据库轮询 worker。
- 可观测性：trace events、jobs、provider health、P50/P95/P99、失败原因和 RAG citation 缺失率。

结论：

项目已经具备“上线验收版本”的工程骨架，可以作为 GitHub 项目和简历项目展示；但真实线上稳定性仍依赖服务器配置、真实 Redis/RDS/OSS smoke、更多真实样本和持续人工反馈。不能声称大规模生产稳定性。

## 2. v0.7.64-v0.7.70 交付清单

  - `scripts/smoke_rq.py`
- `scripts/run_worker.sh` 支持：
  - 本地数据库轮询 worker。

### v0.7.69：Trace Metrics Dashboard

- 新增 `GET /api/metrics/dashboard`。
- 汇总：

  - job 总量、状态分布、成功率、失败原因。

## 3. 上线前必跑 Smoke

PostgreSQL：

```bash
DATABASE_URL=postgresql+psycopg://puzzleops_user:password@rds-host:5432/puzzleops \
PUZZLEOPS_INIT_DB=1 \
python scripts/smoke_postgres.py
```

OSS：

```bash
ASSET_STORAGE_PROVIDER=oss \
ALIYUN_OSS_ENDPOINT=https://oss-cn-xxx.aliyuncs.com \
ALIYUN_OSS_BUCKET=puzzleops-assets \
ALIYUN_OSS_ACCESS_KEY_ID=... \
ALIYUN_OSS_ACCESS_KEY_SECRET=... \
python scripts/smoke_oss.py
```

真实上传下载测试：

```bash
PUZZLEOPS_OSS_SMOKE_UPLOAD=1 python scripts/smoke_oss.py
```

Redis/RQ：

```bash
PUZZLEOPS_JOB_QUEUE_PROVIDER=rq \
REDIS_URL=redis://:<password>@redis-host:6379/0 \
PUZZLEOPS_RQ_QUEUE=puzzleops \
python scripts/smoke_rq.py
```

FastAPI：

```bash
PUZZLEOPS_API_TOKEN=token_jp_1 ./scripts/smoke_api.sh
```

可观测性：

```bash
curl -H "Authorization: Bearer token_jp_1" \
  "http://127.0.0.1:8000/api/metrics/dashboard?country=日本"
```

- `POST /api/jobs/vlm-parse`
- `POST /api/jobs/generate-derivatives`
- `POST /api/jobs/feishu-sync`
- `POST /api/jobs/rag-rebuild`
- `GET /api/jobs/{job_id}`
- `POST /api/jobs/{job_id}/retry`
- `GET /api/traces/{trace_id}`
- `GET /api/metrics/latency`
- `GET /api/metrics/provider-health`
- `GET /api/metrics/dashboard`

权限：

- `viewer`：只读查看 health、RAG、Harness、trace、metrics。
- `operator`：上传图片、发起解析、价值观分析、创建 job。
- `admin`：用户/token 管理、RAG rebuild、job retry、飞书同步确认。

国家隔离：

- 日本 token 只能操作 `country=日本`。
- 法国 token 只能操作 `country=法国`。
- 管理员可配置 `日本|法国`。

## 6. 安全边界

必须遵守：

- `.env` 不提交。
- API token、RDS 密码、OSS AK/SK、飞书密钥不进 GitHub。
- 对外服务必须加 HTTPS、VPN 或服务器防火墙。
- OSS bucket 和 RDS 白名单只开放可信网络。
- 飞书写入必须保留人工确认，不做无确认自动写入。
- 模型输出、价值观判断、风险判断、生成图审核都保留 HITL。

## 7. 当前限制

- `PostgresPuzzleRepository` 已完成 schema 和 smoke，业务读写仍以 SQLite repository 兼容实现为主，后续可逐步迁移到 SQLAlchemy repository。
- Redis/RQ 已完成派发骨架，`execute_job_once()` 的真实业务 handler 仍需逐项接入 Qwen-VL、通义万相、飞书同步、RAG rebuild。
- Metrics dashboard 当前是 API 汇总，不是图形化前端面板。
- 真实样本仍偏小，不能声称大规模生产稳定性。
- 图像相似检索在小样本下容易低置信，低置信策略是“少展示错依据”，不是证明相似检索已经完全可靠。
