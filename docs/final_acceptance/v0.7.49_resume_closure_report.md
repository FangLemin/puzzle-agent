## 项目定位

PuzzleOps Agent 的目标不是训练一个大模型，而是把拼图内容运营的真实流程工程化：

- 运营上传或选择图片。
- VLM 解析主体内容、色彩氛围、构图环境。
- RAG 召回日本/法国价值观与审核规则。
- 参考历史好图/坏图和真实业务指标。
- Agent 生成提需建议、价值观判断、风险提示和排图建议。
- 运营人工确认后，写入飞书多维表格。
- Harness 把每次运行变成可评测、可回放、可对比的 case。

这个项目更适合在面试中包装为：

> 我构建了一个面向出海拼图内容运营的 Agent Harness 系统，核心不是单次 prompt demo，而是围绕多模态理解、RAG 依据、HITL 标注、评测指标、工具调用和飞书落地形成可回放的数据生产闭环。

解释：

- 三段式描述、飞书字段、工具调用这些工程链路已经比较稳。
- 用三项指标直接反推等级效果很差，所以项目已经明确不把三项指标作为主等级预测口径。

### RAG 检索评测

来自 `docs/eval/rag_hard_negative_report.md`：

- Hit@5：100%。
- MRR@5：97%。
- NDCG@5：98%。
- Precision@5：20%。
- Recall@5：100%。
- Hard-negative TopK 率：22%。

解释：

- RAG 能把 expected 文档召回。
- 但 Top5 中仍混入较多同国异主体 hard-negative，因此 citation 有用性偏弱。
- 当前已经做了 citation 强相关过滤和 Top3 截断，但不应声称 RAG 依据完全稳定。

## RAG 设计

离线阶段：

1. 文档加载：
   - 日本/法国价值观规则。
   - 审核风险规则。
   - approved memory。
   - 真实历史样本与 human_gold 样本。
2. Chunk 切分：
   - 按语义边界优先切分。
   - 支持 chunk size 和 overlap 配置。
   - 保留 parent document 元数据。
3. 入库：
   - SQLite 保存 chunk 原文和元数据。
   - 支持 Milvus/Zilliz 作为向量库。
   - 保留 BM25 所需文本字段。
4. Provider：
   - 本地 fallback：`local-token-cosine` 和 `local-rule-rerank`。
   - 真实调用：DashScope embedding 与 `qwen3-rerank`。
   - 远程调用必须显式开启，避免误产生费用。

在线阶段：

1. Query 构造：
   - 国家、JS 分类、运营 tag、主体、主体描述、备注、风险关键词共同组成 query。
2. 多路召回：
   - BM25 负责关键词匹配。
   - 向量召回负责语义匹配。
   - Memory/RAG chunk/harness gold 统一作为候选池。
3. Rerank：
   - 本地或 Qwen rerank 精排。
   - 记录 retrieval trace。
4. Citation 过滤：
   - 保留强相关 citation。
   - 支持 hard-negative parent 屏蔽。
   - 价值观大师最终只拿 Top3 强引用。
5. Prompt 拼接：
   - 把问题、图像证据、RAG citation、风险规则拼接给 LLM。
   - Prompt 要求模型只能引用真实 citation，不足时说明需人工复核。

## Memory 设计

四层 memory：

- 感知记忆：图片解析、VLM 观察、当前视觉证据。
- 短期记忆：当前任务链路状态、生成 trace、临时操作上下文。
- 长期记忆：运营确认后的价值观、偏好、稳定经验。
- 结构化事实：主体、国家、运营 tag、图片路径、gold label、业务指标。

治理机制：

- SQLite 存储 memory。
- 支持状态、过期时间、fingerprint、source memory、人工审核人。
- 草稿、过期、冲突、停用 memory 不进入 RAG。
- 命中 RAG 后回写 hit count 和 last hit time。
- 支持人工批准进 RAG、批准但不进 RAG、驳回、停用和冲突处理。

## Harness 设计

Harness 覆盖任务：

- 试新图解析。
- 价值观匹配。
- 审核风险。
- 等级预测。
- 好图衍生生成。
- 飞书同步字段完整性。

当前可观测内容：

- 数据集概览。
- 真实样本与合成样本区分。
- run 指标。
- case 级 trace。
- failure categories。
- HITL 人工修正。
- RAG runtime stats。
- 生成 trace。

## 好图衍生设计

当前流程：

1. 上传历史好图或参考图。
2. Qwen VLM 解析主体、色彩、构图、文化元素和风险。
3. Agent 生成衍生 prompt。
4. DashScope/通义万相 provider 生成新参考图。
5. 新图再次经过 VLM 解析。
6. 审核规则复检。
7. 运营人工确认。
8. 通过后才进入试新提需表并具备飞书附件同步资格。

边界：

- 生成图只作为参考图和提需素材，不自动视为最终生产图。
- 生成失败、额度不足、VLM 失败、审核失败、未人工确认时不会伪造生成结果。

## 面试高频解释口径

如果被问“你这个 Agent 和普通 prompt demo 有什么区别”：

> 我做的是 Harness 化的业务 Agent。普通 demo 只展示一次模型输出，我这里把输入样本、VLM 解析、RAG citation、工具调用、飞书写入、人工修正、评测指标和版本报告都结构化保存，所以可以回放、对比、定位问题并持续改进。

如果被问“RAG 为什么效果不够好还要写”：

> 我没有把 RAG 包装成已经完美，而是做了 retrieval eval。当前 Hit@5 和 Recall@5 很高，但 Precision@5 和人工 citation 有用性偏低，说明能召回但依据排序不够干净。我进一步引入 hard-negative 评测、citation Top3 过滤和人工反馈沉淀，这体现的是工程化诊断能力。

如果被问“为什么不直接训练”：

> 因为当前错误可能来自 VLM prompt、RAG 召回、历史依据排序、指标标定和国家规则，而不一定是模型参数问题。先用 Harness 拆开评测，确认问题源头后再决定是否后训练，避免用训练掩盖数据和检索问题。

如果被问“真实业务数据够吗”：

> 当前是 45 条真实小样本，适合做可控 benchmark 和面试 demo，不适合宣称线上统计显著性。后续如果要证明业务效果，需要扩充到更大真实样本，并按国家、题材、来源、分发位置做分层评估。

## 下一步建议

优先级从高到低：

1. 继续补齐 50 条真实样本，最好让法国和日本都覆盖坏图、边界图、风险图。
2. 对 RAG hard-negative 失败样例做人工反馈，把不相关 citation 标为 not_useful。
3. 优化历史依据相似度：加入图像 embedding 或更强 subject/culture feature，不只靠文本。
4. 做 Prompt v2/v3 对比报告，只在人工评分提升后再考虑进入主链路。
5. 如果价值观预测仍不稳，再启动后训练，而不是现在直接训练。
